## 一、方案 DOCX 的结构（约 30 页，13 章 + 附录）

| 章 | 内容 | 为什么必须有 |
|---|---|---|
| 封面 + 文档说明 | 编制范围、计价方法、价格水平、估算精度、配套文件 | 替代"版本记录"，客户版不放 V1/V2 |
| 目录 | Word 域，`TOC \o "1-2" \h \z \u` | 交付前必须更新域，否则显示"错误！未找到目录项" |
| 1 项目条件与建设基准 | 规模表、资料差异处理、范围与边界声明、编制依据 | 口径冲突在这里一次性解决 |
| 2 目标与验收指标 | 4 条主线 + 9–12 项可测指标（数值 + 验证方式） | 领导只看这页也能判断值不值 |
| 3 架构与网络 | 五层架构图、拓扑图、跨地块互联比较、接口标准 | 决定能不能换品牌、加系统 |
| 4 假设与容量 | 假设表 + 容量表 + 敏感性表 | 被问"数量哪来"时的挡箭牌 |
| 5 传统智能化 | 7 类 20 子系统，每类给"子系统 / 金额"小表 + 一段说明 | 可按行核减 |
| 6 农业智能化 | 5 类 8 子系统，同上 | 同上 |
| 7 控制与水肥（农业项目必写） | 职责划分、控制权与故障处置、独立保护、六路联动、水力设计八步、轮灌与排液闭环 | 这是"真懂工艺"的证据 |
| 8 计价体系 | 取费表 + 造价构成图 + 口径说明 + 控制额 | 报价能自圆其说 |
| 9 投资估算 | 汇总、分期、分层、选配、档位、运维、效益 | 决策层最关心 |
| 10 界面与责任 | 界面表（谁做什么） | 合同附件，防扯皮 |
| 11 实施与验收 | 里程碑 + 运行验收场景表（8 个场景） | 把"验收"从形容词变成动作 |
| 12 风险 | 6–8 条，带等级与对策 | 显示你想过 |
| 13 待确认 | 逐项给"现状假设 / 影响 / 确认方" | 把不确定性摆到桌面 |
| 附录 A/B | 标准清单、术语 | 显得规范，且真的有用 |

**客户版纪律**：不出现 V1/V2/最终版字样、不出现"与 XX 方案对比"、不出现修订记录。要留痕就留"文档说明"。

## 二、概算 XLSX 的结构（8–9 个工作表）

| 表 | 作用 | 关键点 |
|---|---|---|
| 编制说明 | 范围、口径、精度、复核方式 | 一页说清，别写成长文 |
| 参数与取费 | 费率单元格集中放这里 | **所有公式引用它**，改费率一处生效 |
| 汇总取费 | 取费链逐级 | 每行公式，不写死数 |
| 传统智能化清单 | 逐行 9 字段 | 类型列驱动安装/调试基数 |
| 农业智能化清单 | 同上 | 同上 |
| 可选包 | 6 项，含扣减说明 | 与主预算互斥项要写清 |
| 分层与选配 | 投产必建/运营配套 + 0/1 开关 | 开关用 SUMPRODUCT 汇总 |
| 造价指标 | 单方指标、占比 | 用于横向比价 |
| 校验 | 5 项交叉校验 | **差异必须为 0**，否则不许交付 |

实现要点：

```python
# 费率引用要动态，不要硬编码行号
RATE_ROW = {"install": 36, "debug": 37, ...}
RC = {k: f"参数与取费!$C${v}" for k, v in RATE_ROW.items()}
f_install = f"=(D{r_eq}+D{r_mat})*{RC['install']}"
```

> 真实事故：费率行是动态写入的，公式却硬引 `$C$36`，结果六项费用全 0，肉眼看不出。

## 三、汇报 PPTX 的结构（16–20 页）

| 页 | 要回答的问题 |
|---|---|
| 1 封面 | 项目 + 一句话定位 + 两个总数字 |
| 2 项目条件（4 个 KPI） | 多大、多远、多少栋、覆盖多少 |
| 3 差异结论（如有对照） | 为什么是这个数（三层归因） |
| 4 目标与指标 | 做成什么样算成功 |
| 5 架构图 | 谁管谁 |
| 6 系统全景 | 多少子系统、钱怎么分 |
| 7–8 传统 / 拓扑 | 底座是什么 |
| 9–10 农业 / 控制与水肥 | 生产怎么被控制 |
| 11 平台与追溯 | 数据怎么用 |
| 12 造价构成（图） | 直接费 → 含税怎么来的 |
| 13 投资汇总 | 三个数：直接费、含税、余量 |
| 14 大类构成（图） | 钱花在哪 |
| 15 可选包 | 什么没算进来 |
| 16–17 分层与选配 + 分期档位 | 什么时候做、能不能少做 |
| 18 投资合理性 | 单方指标 vs 行业区间 |
| 19 结尾 | 下一步要客户确认什么 |

排版纪律：16:9、页脚固定、每页一个结论句、表格 ≤6 列、图不放标题（标题在页眉）。

## 四、Office 自动化（Windows）

```powershell
# Word：更新域（目录）+ 统计页数 + 导出 PDF
$w = New-Object -ComObject Word.Application
$w.Visible = $false; $w.DisplayAlerts = 0
$doc = $w.Documents.Open($src)
$doc.Fields.Update() | Out-Null
foreach ($toc in $doc.TablesOfContents) { $toc.Update() }
$doc.Repaginate(); $pages = $doc.ComputeStatistics(2)
$doc.Save(); $doc.ExportAsFixedFormat($pdf, 17); $doc.Close($false); $w.Quit()

# Excel：全量重算（openpyxl 不计算公式）
$xl = New-Object -ComObject Excel.Application
$wb = $xl.Workbooks.Open($xlsx); $xl.CalculateFullRebuild(); $wb.Save(); $wb.Close($true); $xl.Quit()

# PowerPoint：导出 PNG 逐页目检
$app = New-Object -ComObject PowerPoint.Application
$pres = $app.Presentations.Open($pptx, $true, $false, $false)
$pres.Export($dir, "PNG", 1440, 810); $pres.Close(); $app.Quit()
```

**没有 PowerPoint 时**：用 LibreOffice `soffice --headless --convert-to pdf`，再 `pymupdf` 转 PNG。

## 五、Windows 上真实会踩的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 文件被 WPS/Word 占用 | `PermissionError: [Errno 13]` | 先写临时名 → 关闭占用进程 → 覆盖；或直接换名交付 |
| 中文输出乱码 | 控制台 `?`、`UnicodeEncodeError: gbk` | `$env:PYTHONIOENCODING="utf-8"`；脚本内 `print` 前 `.encode("utf-8","replace").decode()` |
| PowerShell 里写 Python 代码 | `@" ... "@` 里的引号/反斜杠被解释，`SyntaxError` | 用 `write` 工具落盘 `.py` 再执行，不要内联 |
| 系统 python ≠ 运行时 python | `ModuleNotFoundError: docx/pymupdf` | 用会话给出的 dsh 运行时 python 全路径 |
| 目录末尾多出空白页 | 39 页变 40 页 | 删掉最后的 `page_break()` |
| 表头孤行 | 表头在页底、表体在下一页 | 给表格段设 `keep_with_next`，或前置分页 |
| matplotlib 中文方块 | 标题变方框 | `fm.fontManager.addfont("C:/Windows/Fonts/msyh.ttc")` |
| 图表标题里 `%` | `ValueError: unsupported format character` | 用 `.format()` 或 `f"5%"` 字面量，避开 `%` 格式化 |

## 六、交付前自检（8 条）

1. 目录已更新域，页码连续；
2. 三件套金额一致（跑 `costing_check.py`）；
3. 概算"校验"页 5 项全为 0；
4. 正文里每个金额能在概算里找到对应行；
5. 假设表与敏感性表覆盖所有标"假设"的行；
6. 边界声明与界面表覆盖所有"不含项"；
7. PPT 每页无溢出、无文字截断（导出 PNG 抽查 ≥5 页）；
8. 客户版无版本号、无内部对比、无"待确认"占位符（`[待确认]` 必须清零或改写为非承诺表述）。
