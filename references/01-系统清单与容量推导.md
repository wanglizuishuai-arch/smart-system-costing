# 01　系统清单与容量推导

算量的全部工作只有一句：**把"要装多少"变成"面积/栋数 × 一条可写下来的规则"。**
写不出规则的量不要进清单，先标"假设"，再进敏感性表。

---

## 一、先解决口径冲突（这一步错，后面全错）

客户资料常见三套面积：规划文本、平面布置图（蓝图）、报建/施工图。处理顺序：

| 优先级 | 依据 | 理由 | 用法 |
|---|---|---|---|
| 1 | 施工图 / 最新蓝图 | 点位与施工以图为准 | 主口径 |
| 2 | 规划文本 | 业态与功能描述最全 | 对照口径 |
| 3 | 招商/宣传材料 | 数字通常取整、偏乐观 | 只做参考，不进清单 |

做法：

1. 建一张"规模对照表"，逐项列 文本 / 蓝图 / 差异 / 采用；
2. 差异 >5% 的项，在方案里单列一节说明影响（差多少点位、多少钱）；
3. 差异 >15% 的项，进"深化前须确认"清单，并给"假设错了会怎样"的一句话。

> 真实教训：玻璃温室文本写 1,440㎡、蓝图 3,360㎡，差 2.3 倍，直接影响控制分区与机电包 60–70 万元。这种差别不写进文档，深化时一定扯皮。

## 二、密度假设（可直接抄，改比例即可）

| 对象 | 假设 | 典型取值 | 依据 |
|---|---|---|---|
| 办公信息点 | 每 8–12㎡ 一个双口 | 办公 810㎡ → 96 点 | 工位密度 1 人/6–8㎡，双口含备用 |
| 研发信息点 | 每 10㎡ 一个 | 720㎡ → 72 点 | 含实验台与设备点位 |
| 厂房信息点 | 每 140㎡ 一个 | 4,000㎡ → 28 点 | 以产线工位与办公角为主 |
| 冷库信息点 | 每 125㎡ 一个 | 4,000㎡ → 32 点 | 含温控与门禁接入 |
| 无线 AP | 每 AP 覆盖 400–600㎡（室内）、800–1,200㎡（室外） | 62 台 | 办公/厂房按 450㎡，室外按 1,000㎡ |
| 摄像机 | 室内每 250–400㎡ 一路；室外按周界 100m/路 + 出入口 | 见下 | 关键点位单算，不做平均 |
| 温室相机 | 每栋 2 路（一条通道 + 一个冠层视角） | 54 栋 → 108 路 | 兼做长势查看，不重复采购 |
| 温室传感器 | 温湿度 2 套/栋、PAR 1、CO₂ 每 3 栋 1、基质 2 | 108/54/18/108 | 冠层与根区代表点 |
| 灌溉分区 | 每栋 2 区（南北或东西） | 54×2 = 108 区 | 单区 ≈ 750–800㎡ |
| BA 点位 | 每台空调/新风 6–8 点、每台水泵 4 点、每台电梯 5 点 | 420 点 | 按设备清单逐台算，不按面积 |
| 门禁 | 每栋 1–2 门，机房/财务/库房单独 | 32 门 | 按管理需要 |
| 能耗计量 | 每栋 1 只电表 + 总表分项；水表按引入管 | 64 只 | 分项计量要求 |

> 密度不是标准，是**约定**。写进文档时永远带上"假设"两个字，并给敏感性。

## 三、容量推导公式（这四组最常被追问）

### 1. 视频存储

```
有效容量(TB) = Σ(路数 × 码率(Mbps) × 86400 × 保存天数) / 8 / 1,000,000 / 有效系数
有效系数 = 1 / (1 + 运行余量) ，运行余量取 20%
```

例：重点 64 路 × 4Mbps × 90 天 + 一般 128 路 × 4Mbps × 30 天
= (64×4×86400×90 + 128×4×86400×30)/8/1e6 = 414.7 TB 原始 → ÷0.8 → **518 TB 有效**，配 520TB。

要点：
- 报"有效容量"而不是"盘位容量"，RAID 校验与热备要扣；
- 重点/一般分级保存，比全线拉长天数便宜得多；
- 码率按 H.265 主码流 4Mbps 取，夜间红外场景可能更高。

### 2. 网络带宽

```
接入带宽 = 并发视频路数 × 码率 × 1.2（余量）
上行带宽 = 峰值业务并发 × 单会话带宽 + 视频回传（若集中存储）
```

- 视频走本地存储时，跨地块只需回传告警与缩略图（≤50Mbps）；
- 集中存储时，跨地块需按 回传路数 × 码率 计，5km 链路必须核算。

### 3. UPS 容量

```
UPS(kVA) = Σ(控制与通信负载 kW) / 功率因数(0.9) × 1.25（裕量）
后备时间(min) = 电池 Ah × 电压 × 0.8 / 负载 kW / 60
```

- 只保障控制、通信、存储与业务设备，**不带动力负载**（泵、风机、卷膜电机）；
- 常见坑：把温室执行机构算进 UPS，容量翻三倍。

### 4. 光缆芯数（跨地块/园区主干）

```
需求芯数 = 业务链路数 × 2（收发）+ 备用 50%
选型取标准芯数：12 / 24 / 48 / 96 芯
```

- 两地块互联建议 ≥24 芯，48 芯可支撑未来分区与视频集中存储；
- 一次性投资 vs 租用专线：自建 ≈ 20–25 万元/5km（含管道协调），租线 4–8 万元/年。

## 四、系统清单骨架（传统 7 类 / 农业 5 类）

传统智能化（按 GB 50314 组织）：

| 类 | 子系统 | 常见追问 |
|---|---|---|
| 一 信息设施 | 综合布线、信息网络、电话交换、信息发布、公共广播、会议、时钟 | 信息点密度、桥架是否重复计 |
| 二 公共安全 | 视频监控、出入口控制、停车管理、周界报警、入侵报警、电子巡更 | 存储天数、周界长度实测 |
| 三 建筑设备 | 楼控 BA、智能照明、能耗计量、电梯监控、污水站 | BA 点位按设备逐台算 |
| 四 机房工程 | 装修、防雷接地、UPS、精密空调、机柜、动环、气体灭火、KVM | 机房面积与 IT 负载是否匹配 |
| 五 综合管路 | 室外管网、手孔、桥架、光缆、两地块互联 | 管沟单价（95 vs 285 元/米） |
| 六 集成平台 | IBMS、接口开发、超融合/服务器、指挥中心大屏、操作台 | 平台级 vs 模块级 |
| 七 实施服务 | 深化设计、第三方检测、培训 | 是否被 5% 费率重复计取 |

农业智能化（设施农业通用）：

| 类 | 子系统 | 关键点 |
|---|---|---|
| 一 设施环境调控 | 日光温室控制、玻璃温室控制、气象与病虫 | 控制器/HMI、传感器组、执行回路与配线 |
| 二 水肥一体化 | 首部与施肥、田间阀控、水源与排液、决策软件 | 首部机组与田间滴灌属机电，须定归属 |
| 三 农业物联网与平台 | 底座、生产管理、追溯、冷链、AI、驾驶舱 | 平台级与模块级差价 5–8 倍 |
| 四 研学与电商多媒体 | 直播间、数字沙盘 | 常被当"面子工程"砍掉 |
| 五 实施服务（农业） | 深化、首季驻场、培训 | 首季驻场 ≥90 天，写进合同 |

> 农业部分真正"陌生"的通常只有"环境调控 + 水肥阀控"两块，其余（网络、视频、平台、追溯、机房）是传统弱电的平移。**这一点要在研判里讲明白，否则领导会以为整块都要从零学。**

## 五、把量变成表（清单行字段）

每行必须有这 9 个字段，缺一不可：

```
类别 | 子系统 | 项目名称 | 规格/型号 | 单位 | 数量 | 单价(不含税) | 类型(设备/材料/软件/服务) | 数量依据
```

- **类型**决定取费：只有"设备 + 材料"计安装费，"设备+材料+软件"计调试费；
- **数量依据**一栏写"面积 × 密度"或"公式"，这是被追问时的唯一挡箭牌；
- 软件与服务单列，不要混进设备里——否则安装费虚高，且毛利率算不出来。

## 六、常见量的错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 桥架与线缆重复计（土建已做公共桥架） | 多算 10–20 万 | 只计公共主通道 + 末端支管，注明"不含土建桥架" |
| 温室相机按安防密度算 | 多买 50% 相机 | 每栋 2 路固定，长势查看复用同一路 |
| 水肥分区按面积除 | 分区数与阀控器数量不匹配 | 每栋 2 区，按栋数算，再加玻璃温室独立区 |
| UPS 带动力负载 | 容量翻 3 倍 | 只带控制/通信/存储/业务 |
| 存储按"路数×天数"粗算 | 差 30% | 用第三节公式，分重点/一般 |
| 机房面积按"预留房间"填 | 与 IT 负载不匹配，后期扩容 | 按机柜数 × 0.8–1.0㎡/柜 反算面积 |
